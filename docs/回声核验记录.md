# 《回声》核验与重建

本次输入为用户提供的三页 PDF，MuseScore Studio 4.7.5 导出。
SHA-256：`fad490a2200cb083a89f2a32c13e040147ead4f4f46133cf95f4e48d7eca0786`。

原谱为 A 大调、4/4、38 小节、两组合唱队各 SATB，共八个独立声部，无伴奏。
谱首仅写 Allegro；120 BPM 是用户确认的练习速度，整曲时间线 76 秒，不是原谱给出的精确速度。

## 数据来源与检查

PDF 含完整的 SMuFL 音乐字符和矢量符干、符杠。此次直接读取这些符号，结合原谱图像核对，
没有将乐谱横坐标距离当作音符时值，也没有压缩或拉伸时值来掩盖超拍。

- `data/verified/hui-sheng.json` 保存八声部逐小节音高、休止、起拍、记谱时值、连音及 PDF 坐标。
- PDF 中 920 个不同坐标的符头全部找到对应的声部音符，未分配符头为 0；
  同音合唱共用符头展开后为 938 个记谱声部音符，延音线合并后为 924 个 MIDI 演奏事件。
- 八声部共 304 个声部小节，每个小节逐事件连续累加严格等于四拍。
- 两队共 462 对 MIDI 演奏事件逐对检查：音高、时值一致，第二队统一延迟两拍。
- 第 8 小节上下声部的附点四分音符／八分音符与四分音符分别保留；
  第 18 小节男高的两个八分音符与男低的一拍持续音独立处理，第二队对应位置同样核验。
- 第 20/21 小节的十六分音符、临时还原号／升号以及声部同音均保留。
- 第一队第 33→34、36→37 小节及第二队第 34 小节内的同音延音线合并为持续音；
  第 18/19 小节不同音高之间的圆滑线不合并。结尾“静”重新起音。
- 分声部明确使用女声／男声音色；两队可独立独听。
- MIDI 经应用实际使用的解析器回读，核对所有事件和共同小节时间线。

## 可复现命令

安装 `tools/requirements.txt`，从仓库根目录执行：

```sh
python tools/audit_hui_sheng.py
python tools/build_hui_sheng.py
npm --prefix choir-studio ci
npm --prefix choir-studio test
```

`audit_hui_sheng.py` 独立从原 PDF 的符头高度、谱号、调号和临时升降号检查账本音高及符头覆盖。
`build_hui_sheng.py` 从账本重建 MusicXML、MIDI、播放 JSON 和原谱图像。
该流程专用于此份已固定散列的 PDF，不声称能自动正确导入任意扫描乐谱。

## 验证边界

上述结果来自源符号检查、原谱图像比对、结构检查和浏览器实际非静音播放，
不等同于音乐人员的逐声部听感签收。显式力度记号保留；渐强渐弱与人声演奏表现仍为练习近似。
原有歌曲的待校订状态不会因此升级。
